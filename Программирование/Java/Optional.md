`Optional` можно представить как контейнер, в которую помещается объект. Он может либо содержать объект типа `T`, либо быть пустым. Такая обёртка помогает избежать работы с `null` напрямую.

### Способы создания
`Optional` не имеет явных конструкторов, но имеет три статических метода для создания экземпляров.

##### Метод `ofNullable()`
Принимает любой объект и создает контейнер. Если передать `null`, будет создан пустой контейнер. Этот метод следует использовать, когда есть вероятность, что объект может быть `null`.
```java
@AllArgsConstructor
public class PersonRepository {

    private final Map<Long, Person> persons;

    public Optional<Person> findById(Long id) {
        return Optional.ofNullable(persons.get(id)); // get() может вернуть null
    }

}
```

##### Метод `of()`
Похож на `ofNullable()`, но если передать `null`, он выбросит `NullPointerException`. Используется, если объект точно не должен быть `null`.
```java
@AllArgsConstructor
public class PersonRepository {

    private final Map<Long, Person> persons;
    
    public Optional<Person> findByLogin(String login) {
        for (Person person : persons.values()) {
            if (person.getLogin().equals(login)) {
                return Optional.of(person);
            }
        }
        return Optional.empty();
    }
}
```


##### Метод empty()
Если объект не найден, нужно вернуть пустой `Optional`. В таком случае лучше использовать метод `empty()`, который создаёт пустой контейнер.
```java
return Optional.empty();
```


### Методы
Рассмотрим основные методы `Optional`.

##### Методы isPresent() и isEmpty()
`boolean isPresent()` позволяет убедиться, что объект внутри есть.
`boolean isEmpty()` - противоположность `isPresent()`.

##### Метод get()
После проверки с помощью методов `isPresent()` или `isEmpty()`, можно извлечь объект из контейнера с помощью метода `T get()`. Если объект внутри контейнера отсутствует, то будет выброшено исключение `NoSuchElementException`.

##### Метод orElse()
Метод `T orElse(T other)` возвращает значение из контейнера, если оно есть, или значение по умолчанию (`other`), если объект отсутствует.

##### Метод map()
Метод `map()` вернет `Optional<Optional<T>>`, если функция, переданная в `map()`, возвращает `Optional`. Чтобы избежать двойного обёртывания, используется `flatMap()`, который “распаковывает” вложенные контейнеры.

##### Метод flatMap()
Метод `map()` вернет `Optional<Optional<T>>`, если функция, переданная в `map()`, возвращает `Optional`. Чтобы избежать двойного обёртывания, используется `flatMap()`, который “распаковывает” вложенные контейнеры.

### Когда стоит использовать Optional
`Optional` в первую очередь предназначен для использования в качестве типа возвращаемого значения метода, когда существует явная необходимость представлять «отсутствие результата» и где использование `null` может вызвать ошибки.

**Замечание**: Метод, возвращающий `Optional`, не должен возвращать `null`., иначе будет выброшено исключение `NullPointerException`.

### Когда НЕ стоит использовать Optional

##### В качестве параметра метода
Если пользователь не знает, что необходимо передать Optional, он может случайно передать null, что приведёт к `NullPointerException`. Вместо этого лучше использовать стандартные проверки на null внутри метода.

##### Как свойство класса
Не стоит использовать `Optional` для объявления полей класса по нескольким причинам:
	 1. **Совместимость с фреймворками**. Некоторые фреймворки вроде Hibernate не могут напрямую мапить поля из базы данных на `Optional` без использования кастомных конвертеров. Однако фреймворки вроде Jackson хорошо интегрируют `Optional`, что может быть полезно в редких случаях, таких как обработка входящих данных через Webhook, когда создание объекта не контролируется явно.
	2. **Производительность и память**. `Optional` создаёт дополнительный объект, который обычно нужен лишь на короткое время. Если использовать его в качестве поля класса, он может оставаться в памяти дольше, что не критично для маленьких приложений, но в больших системах может повлиять на производительность.
	3. **Сериализация**. `Optional` не реализует интерфейс `Serializable`, что затрудняет сериализацию полей. Это вызывает проблемы при работе с распределёнными системами или передачей данных.

Рекомендуется использовать `Optional` только в геттерах класса. Это позволяет работать с отсутствием данных через `Optional`, не обременяя сам объект.

##### Как обертка коллекции
Крайне нежелательно оборачивать коллекции в `Optional`. Коллекции сами по себе являются контейнерами. Вместо возврата `null`, используйте методы для возврата пустых коллекций, такие как `Collections.emptyList()`, `Collections.emptySet()` и другие.
