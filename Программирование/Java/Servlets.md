Servlet - это компонент платформы Java Enterprise Edition (JEE), используемый для веб-разработки. Сервлет используется для принятие запроса, его обработки и отправки ответа. Сервлеты выполняются внутри контейнера.

Контейнер сервлетов - программа, которая запускается на сервере и умеет взаимодействовать с созданными сервлетами. При получении запроса контейнер определяет, какой именно сервлет должен его обработать и передает запрос ему.

### Жизненный цикл сервлета
Контейнер сервлетов создает только один экземпляр сервлета и, следовательно, все запросы сервлета будут обрабатываться этим экземпляром.
Объект сервлета создается либо при запуске движка сервлетов, либо когда сервлет получает первый запрос.
Для каждого запроса запускается поток, который обращается к объекту сервлета.

Этапы:
1. `init()` - используется для создания сервлета контейнером.
2. `service()` - содержит саму логику работы сервлета. Вызывается для обработки запроса и отправки ответа клиенту.
3. `destroy()` - указывает сервлету вырубиться, предварительно очистив используемые ресурсы (память, потоки и т.д.). Вызывается только после завершения всех потоков в методе service() или, если время ожидания истекло.

### Фильтрация
Фильтр – это Java класс, который реализует интерфейс jakarta.servlet.Filter.

Используются для:
- Перехвата запроса от клиента перед отправкой на сервер.
- Обработки ответа сервера перед передачей его клиенту.

#### Жизненный цикл фильтра
1. `init(FilterConfig filterConfig) - используется для создания фильтра контейнером.
2. ==`doFilter(ServletRequest, ServletResponse, FilterChain)` - вызывается контейнером при передаче пары запрос/ответ каждый раз, когда пара передается по цепочке из-за запроса клиента на ресурс в конце цепочки.==
3. `destroy()` - указывает фильтру прекратить работу. Вызывается только после завершения работы всех потоков в методе `doFilter()` фильтра или по истечении таймаута. Также необходимо очистить все ресурсы.

`FilterConfig` - объект, используемый контейнером сервлетом для передачи информации при создании фильтра.

### Multithreading
Каждый запрос сервлета выполняется в отдельном потоке. Каждый поток имеет свой собственный стек, т.е. у каждого потока своя копия локальных переменных для работы. В результате не будет помех между потоками, и не придется беспокоиться о параллельных вызовах. Проблема может возникнуть только при обращении к общему ресурсу.

## Servlets в Spring MVC

`DispatcherServlet` в Spring является центральным компонентом Spring MVC Framework, который выступает в качестве фасадного контроллера. Он принимает все входящие HTTP-запросы, перенаправляет их соответствующим контроллерам и управляет ответами, включая сопоставление обработчиков и разрешение просмотра.
`DispatcherServlet` реализует паттерн "Единая точка входа" (Front Controller)

Схема обработки запросов:
1. HTTP-запрос принимается `DispatcherServlet`.
2. `DispatcherServlet` обращается к Handler Mapping, чтобы определить, какой контроллер должен обрабатывать запрос на основе шаблона URL.
3. Controller обрабатывает запрос и возвращает объект ModelAndView, который содержит данные модели и название представления.
4. Объект ModelAndView содержит данные модели (результат бизнес-логики) и название представления (какой View требуется отобразить).
5. View Resolver преобразует логическое имя представления в физическое представление (например, страницу JSP).
6. View (обычно в формате JSP, HTML и т.д.) рендерится и заполняется данными модели.
7. Отрисованное представление (View) отправляется обратно клиенту HTTP-ответом.

**Замечание**: Только `DispatcherServlet` является наследником класса `Servlet`.
