Этапы исполнения программы на Java:
1. Компиляция исходного кода (.java) в байт-код (.class).
2. JVM выполняет построчно скомпилированный байт-код, но для ускорения применяется JIT компиляция.

Для компиляции исходного кода в байт-код существует компилятор `javac`, входящий в JDK (Java Development Kit). На вход компилятор принимает файл с расширением `.java`, содержащий исходный код программы, а на выходе выдает файл с расширением `.class`, содержащий байт-код, необходимый для исполнения программы виртуальной машиной.

### Classpath
Classpath - это переменная окружения, используемая JVM для поиска и загрузки классов при запуске программы. Она определяет список каталогов, JAR-файлов и ZIP-файлов, к которым JVM должна обращаться для поиска и загрузки файлов классов.

### JAR
JAR - это zip-архив (.jar), предназначенный для упаковки и распространения Java-приложений и библиотек. 

Jar архив содержит файл манифеста `META-INF/MANIFEST.MF`
Манифест представляет описание содержимого архива в виде пар "ключ-значение".
Основные ключи:
- `Manifest-Version`: Определяет версию файла манифеста.
- `Created-By`: Определяет версию и вендора реализации Java, на основе которой сгенерирован этот файл манифеста. Генерируется утилитой jar.
- `Class-Path`: Указывает относительные URL-адреса библиотек, необходимых этому приложению. URL-адреса разделяются одним или несколькими пробелами. Загрузчик классов приложения использует значение этого атрибута для построения своего внутреннего пути поиска.
- `Main-Class`: Содержит имя основного класса приложения, который будет использоваться при запуске.

#### Разновидности JAR
1. Skinny. Содержит только непосредственно написанный код.
2. Thin. Содержит только непосредственно написанный код, а также описание зависимостей (но не сами зависимости). Зависимости подтягиваются из локальных и удаленных репозиториев.
3. Hollow. Содержит только элементы, необходимые для запуска приложения, но не само приложение. По сути, это готовый “сервер приложений”, на котором позже разворачивается приложение.
4. Fat/Uber. Содержит непосредственно написанный код, прямые зависимости приложения, а также информацию, необходимую для полного развертывания.
