**Функциональный интерфейс** (@FunctionalInterface) - интерфейс, содержащий только один абстрактный метод и произвольное количество default и static методов.

**Лямбда-выражение** представляет собой анонимный метод. Такой метод не используется сам по себе, а реализует метод функционального интерфейса.

Лямбда-выражение имеет вид: `(параметр1[, параметры2, ...]) -> {тело_выражения}`

**Целевой тип** есть функциональный интерфейс , для которого было вызвано лямбда-выражение

Пример целевых типов:
```java
Runnable r = () -> System.out.println("Hi"); // целевой тип: Runnable
IntUnaryOperator sign = Integer::signum;     // целевой тип: IntUnaryOperator
IntBinaryOperator add = (a, b) -> a + b;     // целевой тип: IntBinaryOperator; a и b - int
```

==Лямбда-выражение формирует реализацию абстрактного метода функционального интерфейса, который указывает его целевой тип.==

Пример ЛВ в контексте присваивания:
```java
interface MyNumber {
	double getValue();
}

MyNumber num; // объявляется ссылка на функц. интерфейс MyNumber
num = () -> 123.45; // ЛВ присваивается созданной ссылке на интерфейс
```

Когда ЛВ встречается в контексте целевого типа, автоматически создается экземпляр класса, который реализует функциональный интерфейс, а ЛВ определяет поведение абстрактного метода функционального интерфейса. При вызове метода через цель (в данном случае - getValue()) ЛВ выполняется. По сути, код формирует объект.

Пример ЛВ в контексте передачи как аргумента:
```java
@FunctionalInterface
interface StringFunc {
	String func(String n);
}

static String stringOp(StringFunc sf, String s) {
	return sf.func(s);
}
```

#### Захват переменных
Переменные, определенные в области действия ЛВ, доступны внутри самого ЛВ. То есть, ЛВ может:
- использовать переменную экземпляра или статическую переменную;
- имеет доступ к ссылке this (явно и неявно), которая ссылается на вызывающий экземпляр класса, включающего ЛВ.

Но при использовании в ЛВ локальной переменной из его области видимости, происходит захват переменной. Если переменная не final, то она считается effectively final [3]. Это необходимо для обеспечения многопоточной работы, в частности, для избежания состояния гонки.

#### Ссылки на методы
Позволяет обращаться к методу, не инициируя его выполнения. При вычислении ссылки на метод также создается экземпляр функционального интерфейса.

**Виды ссылок:**
- На статические методы
  `имя-класса::имя-метода`
- На методы экземпляра
  `объектная-ссылка::имя-метода`
- На конструкторы
  `имя-класса::new`

### Библиотечные функциональные интерфейсы [4]

```java
// Проверяет соблюдение некоторого условия
interface Predicate<T> {
	boolean test(T t);
}
Predicate<Integer> isPositive = x -> x > 0;

// Выполняет над двумя объектами бинарную операцию и возвращает результат
interface BinaryOperator<T> {
	T apply(T t1, T t2);
}
BinaryOperator<Integer> multiply = (x, y) -> x*y;

// Выполняет над объектом операцию и возвращает результат операции
interface UnaryOperator<T> {
	T apply(T t);
}
UnaryOperator<Integer> square = x -> x*x;

// Представляет функцию перехода от объекта типа T к объекту типа R
interface Function<T, R> {
	R apply(T t);
}
Function<Integer, String> convert = x -> String.valueOf(x) + " долларов";

// Представляет функцию с двумя параметрами типа T и U и результатом типа R
interface BiFunction<T, U, R> {
	R apply(T t, U u);
}
BiFunction<Integer, Integer, Integer> sum = (x, y) -> x + y;

// Выполняет нек. действие над объектом типа T, при этом ничего не возвращая
interface Consumer<T> {
	void accept(T t);
}
Consumer<Integer> printer = x -> System.out.printf("%d долларов \n", x);

// Не принимает аргументы, но возвращает объект типа T
interface Supplier<T> {
	T get();
}
Supplier<Integer> randomValue = () -> (int) (Math.random() * 10) + 1;
```
