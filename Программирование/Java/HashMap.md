Хэш-таблицей называется структура данных, реализующая интерфейс ассоциативного массива ("ключ-значение").

Хэш функция на основании входа (ключа) генерирует целое число (хэш).

В HashMap хэш-таблица реализована на основе динамического массива односвязанных списков. Причем поддерживается хранения произвольного количества null в качестве значений и одного null в качестве ключа.

buckets - элементы массива, которые используются для хранения отдельно взятых узлов. Каждый из бакетов является коллекцией (списком или деревом).
Узлами являются объекты класса Node со следующей структурой:

Поля Node:
- `int hash` - хэш текущего узла
- `K key` - ключ узла
- `V value` - значение узла
- `Node<K,V> next` - ссылка на следующий узел бакета (если коллизия есть)

### Структура класса
#### Поля класса
- `transient Node < K, V> [] table` – сама хеш-таблица, реализованная на основе массива, для хранения пар «ключ-значение» в виде узлов.
- `transient int size` — количество пар «ключ-значение»;
- `int threshold` — предельное количество элементов, при достижении которого размер хэш-таблицы увеличивается вдвое.
  Рассчитывается по формуле: `threshold = (capacity * loadFactor)`;
- `final float loadFactor` — этот параметр отвечает за то, при какой степени загруженности текущей хеш-таблицы необходимо создавать новую хеш-таблицу, т.е. как только хеш-таблица заполнилась на 75% (значение по умолчанию), будет создана новая хеш-таблица с перемещением и перехэшированием в неё текущих элементов.

#### Константы
- `static final int DEFAULT_INITIAL_CAPACITY = 1 << 4` — емкость хеш-таблицы по умолчанию (16);
- `static final int MAXIMUM_CAPACITY = 1 << 30` — максимально возможная емкость хеш-таблицы (приблизительно 1 млрд.);
- `static final float DEFAULT_LOAD_FACTOR = 0.75f` — коэффициент загрузки, используемый по умолчанию;
- `static final int TREEIFY_THRESHOLD = 8` — это «порог» количества элементов в одной корзине, при достижении которого внутренний связный список будет преобразован в древовидную структуру (красно-черное дерево).
- `static final int UNTREEIFY_THRESHOLD = 6` — если количество элементов в одной корзине уменьшится до 6, то произойдет обратный переход от дерева к связному списку;
- `static final int MIN_TREEIFY_CAPACITY = 64` — минимальная емкость (количество корзин) хеш-таблицы, при которой возможен переход к древовидной структуре. Т.е. если в хеш-таблице по крайней мере 64 бакета и в одном бакете 8 или более элементов, то произойдет переход к древовидной структуре.

**Замечание**: capacity должна быть степенью двойки

#### Особенности вычисления хэш-кода для ключа
Для вычисления хэша ключа используется встроенная функция в HashMap.hash() вместо `Object.hashCode()` поскольку он может быть реализован так, что только нижние биты будут заполнены. Например, для маленьких значений `Integer`, `Float` будут заполнены только нижние биты хеш-кодов. В таком случае ключи будут скапливаться в нижних ячейках, а верхние будут оставаться пустыми. Поэтому старшие биты хеша подмешиваются в младшие, чтобы улучшить распределение по бакетам.
```java
static final int hash(Object key) {
	int h;
	return (key == null) ? 0 : (h = key.hashCode()) ^ (h >>> 16);
}
```

### Проверка ключей на равенство
Для проверки элементов HashMap на равенство используется следующее выражение:
```java
(p.hash == hash && ((k = p.key) == key || (key != null && key.equals(k))))
```

### Добавление элемента
0. Если таблица не создана или пустая, то вызывается `resize()`.
1. Вычисляется хэш ключа.
2. Вычисляется индекс бакета (ячейки массива) по формуле: 
   `i = (длина_массива - 1) & hash`.
3. Создается объект Node.
4. Если в бакете пусто, то элемент добавляется в него.
5. Если бакет не пустой, то хэш и ключ нового элемента поочередно сравниваются с хешами и ключами существующих элементов и, при совпадении этих параметров, значение элемента перезаписывается. Если совпадений не найдено, элемент добавляется в конец списка.

**Замечание**: При создании объекта HashMap, сама хэш-таблица не создается. Она создается только при первом добавлении элемента. Инициализацию выполняет метод `resize()`.

### Получение элемента
1. Вычислить хэш ключа.
2. Вычисляется индекс бакета (ячейки массива) по формуле: 
   `i = (длина_массива - 1) & hash`.
3. Сравнить ключ первого элемента с переданным.
	1. Если они равны – вернуть значение, иначе выполнить проверку для следующего элемента, если он существует.
	2. Если следующий объект Node равен null, вернуть null.

### Удаление элемента
1. Вычисляется хэш ключа.
2. Вычисляется индекс бакета (ячейки массива) по формуле:
   `i = (длина_массива - 1) & hash`.
3. Если в бакете только один объект (проверяем его поле `next` на null), сравниваем ключи по формуле [[#Проверка ключей на равенство]]. Если нашлось совпадение, то удаляем его (фактически присваиваем его ссылке значение null) и возвращаем значение этого ключа.
4. Если в бакете больше одного элемента, проверяем каждый элемент, пока не найдем элемент или не достигнем конца списка. Если элемент найден, то удаляем его и переопределяем ссылку next (иначе связность списка сломается).
5. Возвращаем null, если элемент не был найден.

### Сложность операций
В среднем случае:
- Поиск - O(1).
- Добавление - O(1).
- Удаление - O(1).
В худшем случае (при использовании списка):
- Поиск - O(n).
- Добавление - O(n).
- Удаление - O(n).
В худшем случае (при использовании дерева):
- Поиск - O(log n).
- Добавление - O(log n).
- Удаление - O(log n).
