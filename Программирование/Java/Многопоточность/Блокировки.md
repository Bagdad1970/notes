Блокировка позволяет контролировать доступ к общему ресурсу со стороны нескольких потоков. Обычно блокировка обеспечивает монопольный доступ к общему ресурсу, но некоторые блокировки могут допускать одновременный доступ к общему ресурсу, например блокировка чтения в ReadWriteLock.

## Интерфейс Lock
```java
interface Lock {
	void lock();
	void lockInterruptibly() throws InterruptedException;
	Condition newCondition();
	boolean tryLock();
	boolean tryLock(long time, TimeUnit unit);
	void unlock();
}
```

Методы `Lock`:
- `void lock()` - ожидает получения блокировки
- `void lockInterruptibly() throws InterruptedException`
- `Condition newCondition()` - возвращает объект Condition, который связан с текущей блокировкой. 
- `boolean tryLock()` - пытается получить блокировку. Если блокировка получена, то возвращает true, иначе возвращает false. В отличие от `lock()` не ожидает получения блокировки, если ее нельзя получить
- `boolean tryLock(long time, TimeUnit unit)` - похожа на `tryLock()`, но ожидает заданное время, прежде чем прекратить попытки получить блокировку.
- `void unlock()` - снимает блокировку

Реализации `Lock` аналогичны [[synchronized & volatile#Synchronized|synchronized]] , но дают большую гибкость в управлении блокировками. Например, поток может в одном методе заблокировать ресурс, а уже в другом отпустить его.

Для работы с блокировкой должна использоваться конструкция следующего вида:
```java
Lock locker = ...;
locker.lock();
try {
	// работа с критической секцией
}
finally {
	locker.unlock();  // освобождать ресурс строго в finally
}
```
