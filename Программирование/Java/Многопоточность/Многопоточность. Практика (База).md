При запуске программы немедленно начинает выполняться поток main - главный поток программы.

Свойства главного потока:
- является потоком, из которого будут порождаться другие "дочерние" потоки;
- часто заканчивает выполнение последним, поскольку выпол­няет разнообразные действия по завершению работы.

## Приоритеты потоков
Каждый поток имеет приоритет, который влияет на то, как JVM распределяет время процессора между потоками. Приоритеты потоков служат **подсказкой** для планировщика потоков JVM при принятии решения о том, какой поток выполнить следующим. Однако окончательное решение о распределении времени процессора зависит от реализации JVM и ОС.

Потоки с более высоким приоритетом, как правило, получают больше процессорного времени, но **это не гарантирует**, что они будут всегда выполняться раньше потоков с более низким приоритетом. Приоритеты лишь помогают JVM принимать решение, но не являются обязательными для исполнения.

Приоритеты потоков задаются числами от 1 до 10:
- **MIN_PRIORITY (1)**: Минимальный приоритет;
- **NORM_PRIORITY (5)**: Нормальный приоритет (по умолчанию).;
- **MAX_PRIORITY (10)**: Максимальный приоритет.


Способы создания потока:

1. наследование от Thread. 
```java
class MyThread extends Thread {
	@Override
    public void run() {
        // Код для выполнения в отдельном потоке
    }
}
```

2. реализация Runnable 
```java
@FunctionalInterface
interface Runnable {
	void run();
}

class MyThread implements Runnable {
	@Override
	    public void run() {
        // Код для выполнения в отдельном потоке
    }
}
```

### Жизненный цикл потока

![[Pasted image 20260221001738.png]]

**NEW** - Поток создан, но ещё не запущен. Возникает сразу после создания объекта `Thread`, но до вызова метода `thread.start()`. В этом состоянии поток не готов к выполнению и не потребляет системные ресурсы.

**RUNNABLE** - Поток переходит в это состояние после вызова метода `thread.start()`. В этом состоянии поток считается готовым к выполнению и может быть выбран планировщиком потоков для выполнения на процессоре. Поток может фактически выполняться или ожидать своей очереди на выполнение.

**RUNNING** - поток выполняет свою работу.

**WAITING** - Поток находится в состоянии бессрочного ожидания, пока другой поток не разбудит его. Происходит при вызове методов `object.wait()`, `thread.join()` без таймаута. Поток остаётся в этом состоянии, пока не получит уведомление или пока другой поток не завершится (в случае `thread.join()`).

**TIME_WAITING** - Похожее на состояние WAITING, но с указанным временем ожидания. Поток переходит в это состояние при вызове методов `Thread.sleep()` или `thread.join(long timeout)` с указанием таймаута. По истечении времени ожидания поток автоматически возвращается в состояние RUNNABLE.

**BLOCKED** - Поток переходит в это состояние, при попытки войти в синхронизированный блок или метод, доступ к которому в данный момент удерживается другим потоком. Как только монитор освобождается, поток возвращается в состояние RUNNABLE.

**TERMINATED** - Поток переходит в это состояние, когда метод `thread.run()` завершает своё выполнение либо из-за нормального завершения, либо из-за неперехваченного исключения. В этом состоянии поток больше не может быть перезапущен.

### Методы управления потоками
`thread.start()` -> RUNNABLE. Создает новый поток и вызывает метод `run()` в этом новом потоке

`thread.run()`. Содержит код, который будет выполняться в потоке. Если вызвать `run()` напрямую, код будет выполнен в текущем потоке, как обычный метод, и новый поток не будет создан.

`Thread.sleep()` -> `TIME_WAITING`. Приостанавливает текущий поток (переводит в TIME WAITING) на определенный период времени, освобождая ресурсы процессора для других потоков.
`Thread.sleep(1000)  #  приостановит поток на 1000 миллисекунд`

`object.wait()`, `object.wait(long timeout)` -> RUNNABLE. Заставляет поток отказаться от процессорного времени, а также снять любые блокировки объектов. 

`object.notify()` -> `RUNNABLE`. Возобновляет работу потока, у которого ранее был вызван метод `wait()`.

`object.notifyAll()` -> `RUNNABLE`. Возобновляет работу всех потоков, у которых ранее был вызван метод `wait()`.

`thread.join()` -> `WAITING`. Ожидает завершение потока. Позволяет синхронизировать выполнение потоков, обеспечивая выполнение одного потока строго после завершения другого.

`Thread.yield()` -> `RUNNABLE`. Подсказывает планировщику, что текущий поток готов отказаться от использования процессора в текущем режиме. Планировщик может проигнорировать эту подсказку.

### Прерывание потока
==Почему stop устарел==

Поток может остановиться либо после выполнение метода run(), либо по сигналу другого потока. Причем, поток сам решает как обрабатывать этот сигнал: может завершиться, а может и проигнорировать его.

Методы для работы с прерываниями:
- `thread.interrupt()`. Отправляет сигнал прерывания потоку, устанавливая флаг прерывания в true. Поток должен сам проверить этот флаг и принять решение о завершении работы.
- `thread.isInterrupted()`: Проверяет, был ли поток прерван, **не сбрасывая** флаг прерывания.
- `Thread.interrupted()`: Статический метод, который проверяет флаг прерывания текущего потока, **сбрасывая его**.

```java
public static void main(String[] args) {  
	Thread threadLong = new Thread(() -> {  
		int count = 0;  
		while (!Thread.currentThread().isInterrupted()) {  
			count++;  
		}  

		System.out.println("Успели обработать: " + count);  
		System.out.println("Долгий поток завершен");  
	});  

	Thread threadShort = new Thread(() -> {  
		try {  
			Thread.sleep(10);  
			System.out.println("Короткий поток завершен");  
		} catch (InterruptedException e) {  
			throw new RuntimeException(e);  
		}  
	});  

	threadShort.start();  
	threadLong.start();  

	try {  
		threadShort.join();  
		threadLong.interrupt();  
	}  
	catch (InterruptedException e) {  
		e.printStackTrace();  
	}  
}  
```

**Замечание**: Если поток прерывается во время выполнения блокирующих операций (`sleep()`,  `wait()` или `join()`), выбрасывается `InterruptedException`. В таком случае важно корректно обработать это исключение, чтобы завершить поток безопасно.

```java
public class BlockingThreadExample {

    public static void main(String[] args) {
        Thread blockingThread = new Thread(() -> {
            try {
                for (int i = 0; i < 5; i++) {
                    System.out.println("Блокирующий поток работает... " + i);
                    Thread.sleep(1000);
                }
            } catch (InterruptedException e) {
                System.out.println("Блокирующий поток был прерван.");
                return;  // Завершаем работу потока
            }
            System.out.println("Блокирующий поток завершил свою работу.");
        });
        
        blockingThread.start();
        
        try {
            Thread.sleep(3000);
        } catch (InterruptedException e) {
            e.printStackTrace();
        }
        
        blockingThread.interrupt();
    }
}
```

## Потоки-демоны (Daemon threads)
В Java процесс завершается тогда, когда завершается последний его поток. Даже если метод main() уже завершился, но еще выполняются порожденные им потоки, система будет ждать их завершения.

Однако это правило не относится к особому виду потоков – демонам. Если завершился последний обычный поток процесса, и остались только потоки-демоны, то они будут принудительно завершены и выполнение процесса закончится.

Поток-демон (Daemon thread) - фоновый поток с низким приоритетом, обслуживающий другие потоки. Используется для логирования, сборки мусора, мониторинга и т.д.
Метод `thread.setDaemon(true)` позволяет сделать поток демоном.
