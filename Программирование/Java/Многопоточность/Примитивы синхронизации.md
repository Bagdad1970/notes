Примитивами синхронизации называются низкоуровневые механизмы (объекты операционной системы или языка программирования), которые используются для координации работы потоков или процессов при доступе к общим ресурсам. Такие примитивы предотвращают состояние гонки.

К примитивам относятся:
- Семафоры
- Мьютексы
- Мониторы

### Семафор
Семафор - это синхронизатор, который ограничивает количество потоков, одновременно имеющих доступ к критической секции или ресурсу. В основе семафора лежит счётчик, над которым можно производить две **атомарные блокирующие** операции:
- `counter += 1`. Означает, что поток прекращает использование ресурса, и теперь другой поток может использовать ресурс.
- `counter -= 1`. Означает, что поток запрашивает разрешение на доступ к ресурсу. Если `counter > 0`, разрешение предоставляется, а счетчик уменьшается на 1. Если же `counter == 0`, то запрос отклоняется.

**Замечание**: Семафор может освобождаться любым потоком или процессом, который его захватил.

В Java использует класс `java.util.concurrent.Semaphore`.
```java
class Semaphore {

	// fields
	
	public Semaphore(int permits) {...}
	public Semaphore(int permits, boolean fair) {...}
	
	public void acquire() {...}
	public void acquire(int permits) {...}  // (1)
	
	public void release() {...}
	public void release(int permits) {...}  // (2)
	
	...
}
```

Параметры конструкторов:
- `int permits` — начальное и максимальное значение счетчика. Определяет сколько потоков одновременно могут иметь доступ к общему ресурсу;
- `boolean fair` — устанавливает порядок доступа к ресурсу. Если `fair = true`, доступ предоставляется ожидающим потокам в том порядке, в котором они его запрашивали. Если же он равен `fair = false`, порядок будет определять планировщик потоков.

Методы:
`acquire()` - запрашивает одно разрешения у семафора для доступа к критической секции. 
`acquire(int permits)` - запрашивает несколько разрешений у семафора для доступа к критической секции. 
`release( )` - освобождает одно разрешение. 
`release(int permits)` - освобождает несколько разрешений. 

### Мьютекс
Мьютекс является одноместным семафором (`counter = 1`), с той лишь разницей, что мьютекс должен освобождаться только тем потоком, который его захватил. Мьютекс позволяет занимать критическую секцию только одному потоку, пока другие должны ждать освобождения.
Если мьютекс заблокирован, вызывающий поток блокируется до тех пор, пока мьютекс не освободится. Если на мьютексе заблокировано несколько потоков, то произвольно выбирается один из них, которому разрешается войти в критическую секцию.






### Монитор
Монитор обеспечивает потоку эксклюзивный доступ к ресурсу. Для реализации монитора используется мьютекс. Монитор являются конструкцией языка, поэтому компилятор или интерпретатор знает об их особенностях и способен обрабатывать вызовы процедур монитора не так, как вызовы всех остальных процедур. Обычно при вызове процессом процедуры монитора сначала проверяется активность других процессов внутри монитора. Если какой-нибудь другой процесс будет активен, вызывающий процесс будет приостановлен до тех пор, пока другой процесс не освободит монитор. Если монитор никаким другим процессом не используется, вызывающий процесс может в него войти.
