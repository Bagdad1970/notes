## Интерфейсы и Абстрактные классы
`Iterable<T>` - реализация этого интерфейса позволяет объекту быть целью инструкции "for-each loop".

`Collection<T>` - определяет основные методы работы с простыми наборами элементов, которые являются общими для всех реализаций (size(), isEmpty() и т.д.), а также методы для работы со Stream API.

`Set` - представляет неупорядоченную коллекцию, которая не может содержать дубликаты.

`Queue` - представляет LIFO и FIFO структуры данных.

`SortedSet` - элементы упорядочиваются в соответствии с их естественным порядком или с помощью Comparator. Итератор проходится по набору в порядке возрастания элементов.

`Deque` - линейная коллекция, которая поддерживает вставку и удаление элементов с обоих концов.

`List` - позволяет реализовать упорядоченную коллекцию. Доступ к элементам возможен через индексы и значения.

`Map` - Представляет ассоциативный массив. Не может содержать повторяющихся ключей и ключ может относиться только к одному значению. Map предоставляет три вида коллекций, которые позволяют просматривать содержимое как коллекцию ключей, значений или сопоставлений ключ-значение. Порядок хранения определяется как порядок, в котором итераторы в представлениях коллекции карты возвращают свои элементы.

`SortedMap` - элементы упорядочиваются в соответствии с естественным порядком ключей (по возрастанию) или с помощью компаратора.

`NavigableMap` - обеспечивает возможность получения элементов коллекции относительно других элементов.

`AbstractMap` - содержит скелет реализации Map, что позволяет уменьшить усилия, необходимые для реализации Map.

## Реализации
### Реализации List
1. `Vector` - (synchronized) реализация динамического массива.
2. `ArrayList` - (not synchronized) Реализация интерфейса `List` с изменяемым размером массива. Разрешает использование всех элементов, включая null. Предоставляет методы для управления размером массива. (Примерно эквивалентен `Vector`, но не синхронизирован)
3. `Stack` - представляет LIFO структуру. Следует использовать `Deque` вместо `Stack`.
4. `LinkedList` - (not synchronized) представляет двусвязный список.

### Реализации Set
1. `HashSet` - (not synchronized) основана на `HashMap`. Ключ представляет добавляемый элемент, а в качестве значения используется new Object() т.е. пустой объект.
2. `TreeSet` - (not synchronized) элементы упорядочиваются в соответствии с их естественным порядком или с помощью `Comparator`, указанного в конструкторе.
3. `LinkedHashSet` - (not synchronized) элементы располагаются в двусвязном списке в порядке вставки. Но это приводит к тому что операции выполняются дольше, чем для `HashSet`.
