~={red}**Важное замечание**=~: Загрузка классов описана для HotSpot JVM, в других реализациях процесс может отличаться.

При запуске приложения JVM в первую очередь загружает в память необходимые классы.

Загрузка класса состоит в поиске соответствующего файла `.class` на диске, чтении его содержимого и передачи его в среду выполнения JVM, которая предназначена для исполнения приложения. 

Система загрузчиков классов обеспечивает гибкость загрузки классов из различных источников - не только из локальной файловой системы, но и по сети, из базы данных или даже сгенерированных налету.

Этапы системы загрузки классов:
1. Загрузка
2. Линковка
3. Инициализация

## Загрузка
Процесс начинается с того, что загрузчику класса (ClassLoader) необходимо найти определенный класс, что может быть инициировано самой JVM, или вызвано явно командой в коде. Задача заключается в том, чтобы по имени класса (например, `java.lang.String`) получить соответствующий файл класса (например, `String.class`), хранящегося на диске, и загрузить его в память JVM. Приче классы загружаются лениво.

Этап загрузки — это не одиночный акт, а иерархическая эстафета. Каждый ClassLoader, родительский и дочерний, работает совместно, передавая эстафету ответственности до тех пор, пока нужный класс не будет загружен.

Основополагающими принципами, определяющими этот скоординированный процесс загрузки классов, являются:
- **Видимость (Visibility)**: Дочерний ClassLoader может видеть классы, загруженные его родителем, но не наоборот, что обеспечивает инкапсуляцию;
- **Уникальность (Uniqueness)**: Класс, загруженный родителем, не будет повторно загружен его дочерним классом, что повышает эффективность;
- **Иерархия делегирования (Delegation Hierarchy)**: Если дочернему загрузчику нужно найти класс, то он сначала передает запрос родителю (родитель также может быть потомком). Если родитель не смог найти класс, то дочерний загрузчик сам начинает поиск. Если по итогу класс не будет найден, то будет выброшено `ClassNotFoundException`.

### Загрузчики

#### Bootstrap Classloader
Bootstrap ClassLoader написан на native коде и встроен в JVM. Он отвечает за:
1. Загрузку основных библиотек необходимых для запуска JVM, которые расположенны в `java.base` модуле (`java.lang`, `java.util` и т.д.), .
2. Загрузку остальные загрузчиков т.к. они являются объектами `java.lang.ClassLoader`.

#### Platform ClassLoader
Загружает классы платформы, в том числе API-интерфейсы платформы Java SE, классы их реализации и специфичные для JDK классы среды выполнения.

Получается, что Bootstrap загружает основные классы необходимые для запуска JVM, а Platform - публичные типы системных модулей, которые могут понадобиться.

#### Application ClassLoader
Application ClassLoader (System ClassLoader) загружает классы самой программы и библиотеки зависимостей, которые были явно или неявно переданы JVM при старте приложения через параметр `classpath`.

Этот загрузчик является родителем основного потока приложения, и будет являться родителем ваших собственных загрузчиков классов.

В дополнение к трем рассмотренным основным загрузчикам, можно создавать свои собственные, пользовательские загрузчики классов, непосредственно в Java программах, позволяя обеспечить независимость приложений

Пример вывода загрузчиков классов:
```java
import java.sql.Connection;  
  
class MyClass { }  
  
class Main {  
    public static void main(String[] args) {  
  
        // Bootstrap ClassLoader
        System.out.println(String.class.getClassLoader()); // (1)
		
		// Platform ClassLoader 
        System.out.println(Connection.class.getClassLoader());
        
	    // Application ClassLoader  
        System.out.println(MyClass.class.getClassLoader());    
    }  
}
```
(1) - `getClassLoader()` возвращает null, если загрузчик класса является Bootstrap ClassLoader.


## Линковка
Процесс линковки выполняется в три этапа:
1. Верификация
2. Подготовка
3. Разрешение ссылок (resolution)

#### Верификация
Проверяется, что скомпилированный байт-код корректен:
- Двоичное представление класса или интерфейса корректно.
- Класс или интерфейсы не нарушают семантику языка.
- Ссылки на другие классы или интерфейсы действительны

При нарушении этих условий будет выброшена ошибка `VerifyError`.

#### Подготовка
Выделяется память под статические поля класса или интерфейса, и они инициализируются значением по умолчанию.
На этом этапе никакой пользовательский код не выполняется

#### Разрешение ссылок (resolution)
На этом этапе анализируются символические ссылки в байт-коде и определяется на какие реальные методы, поля, классы и т.д. в памяти они указывают.

Когда класс только загружается, JVM ещё не знает, на какой конкретно метод или поле в памяти указывает символическая ссылка. JVM определяет эту ссылку при первом использовании (**зависит от реализации JVM**) и сохраняет результат в пуле констант времени выполнения, поэтому последующие обращения происходят быстрее т.к. адрес уже сохранен и снова его искать не нужно.

Стоит отметить, что спецификация JVM позволяет использовать два подхода:
- **ленивый**. Каждая ссылка разрешается при первом использовании
- **жадный**. Все ссылки разрешаются сразу на этапе верификации.

Пример:
```java
System.out.println("Hello, World!");
```

Пул констант в этом случае будет хранит:
1. Полное имя класса `java/lang/System`
2. Имя поля `out`
3. Дескриптор поля `Ljava/io/PrintStream;`
4. Имя метода `println`
5. Дескриптор метода `(Ljava/lang/String;)V` (означает: принимает строку, возвращает значение void)
6. Строку `"Hello, World!"`

JVM использует эти символические ссылки во время выполнения программы, чтобы найти реальный метод или поле в памяти.

==Если класс найден, но искомый метод не существует - выбросится ошибка `NoSuchMethodError`.==
==Если указанный класс не найден - выбросится ошибка `NoClassDefFoundError`.==
==Если же ссылки существуют, но не могут быть разрешены, то будет выброшена ошибка `NoClassDefFoundError`.==


## Инициализация
Статическим переменным присваиваются их фактические значения, как определено в коде, и исполняются статические блоки. Статические блоки выполняются потокобезопасно и только при первом активном использовании класса (например, при создании экземпляра, вызове статического метода или обращении к статическому полю, которое не является константой времени компиляции).

Под константой времени компиляции подразумеваются литералы или значения `static final` примитивов или строк, которые вычисляются компилятором заранее и жестко вписываются в байт-код.
