~={red}**Важное замечание**=~: Процесс исполнения основан на реализации HotSpot JVM, в другие реализациях процесс может отличаться.

Execution engine интерпретирует и выполняет байт-код, преобразуя его в машинный код. В процессе работы execution engine взаимодействует с различными областями памяти JVM.

Execution engine состоит из:
1. Интерпретатора
2. JIT-компилятора
3. [[Garbage Collector|Сборщика мусора]]

### Интерпретатор
Интерпретатор выполняет байт-код инструкцию за инструкцией без предварительной компиляции в машинный код.

### JIT-компилятор
В традиционных компилируемых языках машинный код генерируется до запуска программы. В Java сначала  байт-код интерпретируется, что может приводить к повторным накладным расходам при выполнении часто используемых участков.

Для повышения эффективности исполнения программы используется JIT-компиляция (Just-In-Time). Во время выполнения JVM собирает статистику о поведении программы, отслеживая часто вызываемые методы и часто выполняемые участки кода (горячие точки). JIT-компилятор компилирует такие участки в нативный машинный код, который затем сохраняется и исполняется напрямую, минуя повторную интерпретацию. Такой подход позволяет существенно ускорить само выполнение программы, но требует дополнительное время на запуск приложения и дополнительную память на сохранение горячих участков кода.

==JIT-компилятор также выполняет ряд оптимизаций, которые позволяют уменьшить накладные расходы исполнения: встраивание методов (inlining), удаление кода, который никогда не запускается (мертвый код), оптимизацию циклов и анализ времени жизни объектов (escape analysis).==
