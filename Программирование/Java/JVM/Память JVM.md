# Общие области данных
Общие области данных используются всеми потоками программы. Они создаются при запуске JVM и уничтожаются при её завершении.
К общим областям относятся:
1. Куча
2. Область методов

### Куча
Создание кучи происходит при запуске JVM, а ее уничтожение - при прекращении работы.

Куча - это область данных среды выполнения, где хранятся все объекты. При создании объекта или массива, JVM находит в куче доступную память и выделяет ее объекту. Память в куче автоматически управляется [[Garbage Collector|сборщиком мусора]].

Куча может иметь фиксированный размер или расширятся и ужиматся, если это допустимо. Память для кучи не обязательно должна быть непрерывной.

Если сборщик мусора не может освободить достаточно места для создания нового объекта, JVM выдаст ошибку `OutOfMemoryError`.

### Область методов (Method Area)
Создается при запуске JVM и удаляется только при завершении работы JVM.

Область методов - это общая область данных в JVM, в которой хранятся структуры для каждого класса, такие как пул констант времени выполнения, данные полей и методов, а также код для методов и конструкторов.

В частности, загрузчик классов загружает байт-код класса и передает его в JVM. Затем JVM создает внутреннее представление класса, которое используется для создания объектов и вызова методов во время выполнения. Это внутреннее представление собирает информацию о полях, методах и конструкторах классов и интерфейсов.

Если доступного пространства в области методов недостаточно для загрузки нового класса, JVM выдаст `OutOfMemoryError`.

#### Пул констант времени выполнения
Создается при создании класса или интерфейса виртуальной машиной.

Скомпилированный файл `.class` в начале имеет секцию Constant Pool (пул констант), в которой хранятся литералы; имена классов, полей, методов. Пул констант действует как общий список повторно используемых частей, на которые может указывать остальная часть файла.

Пул констант времени выполнения содержит несколько видов констант, начиная от литералов, известных во время компиляции, и заканчивая ссылками на методы и поля, которые должны быть разрешены во время выполнения.

#### Литералы
Литералы представляют числа (int, double, float, long) и строки.

```java
int x = 100;  
float y = 3.14f;
String str = "string";
```

Литералы в байт-коде не задаются жестко везде, где они используются. Вместо этого каждое из этих значений сохраняется в пуле констант. Затем байт-код ссылается на них по индексу, используя такие инструкции, как `ldc` (load constant). Это позволяет переиспользовать значения без выделения дополнительной памяти.

Это означает следующее:
```java
String a = "test";
String b = "test";

a == b // будет true (1)
```
(1) - оба строковых литерала будут ссылаться на одну и ту же запись в пуле констант. Когда JVM выполняет этот код, она проверяет встроенную таблицу строк перед созданием нового объекта String. Если такой объект уже существует, он используется повторно.

#### Ссылки на методы, поля и классы
Пул констант также содержит ссылки на объекты, классы и методы, с которыми взаимодействует программа. Ссылки являются символьными т.е. это не ссылки на адрес памяти. Это означает, что они хранят такую информацию, как имя класса, имя метода и дескриптор (компактная подпись, показывающая типы параметров и возвращаемых значений). Далее эти ссылки будут использоваться в процессе [[Class Loader#Разрешение ссылок (resolution)|разрешения ссылок]]



Также в пуле констант символические ссылки живут до тех пор, пока не будут разрешены. Он позволяет держать class-файл **несвязанным (decoupled)** с другими классами, от которых он может зависеть. Это даёт Java-программам возможность загружать всё **по требованию (on demand)**, а не связывать всё намертво на этапе компиляции.

# Области данных потока
Области данных потока создаются при создании потока и уничтожаются при его завершении.
К таким областям данных относятся:
1. PC регистр
2. Стек
3. Native method stacks

### PC регистр
Каждый поток JVM имеет свой регистр PC (program counter).
Каждый поток выполняет код одного метода в любой момент времени. Поведение PC зависит от характера метода:
- Для не-native метода регистр PC хранит адрес текущей выполняемой команды
- Для native метода регистр PC имеет неопределенное значение

Жизненный цикл регистра PC зависит от жизненного цикла его потока.

### Стек
Каждый поток JVM имеет свой собственный стек.
Стек хранит фреймы. При вызове метода в стек добавляется фрейм, а при выходе из метода или генерации исключения, фрейм удаляется.

Стек JVM позволяет отслеживать выполнение программы и регистрировать трассировку стека по требованию.

Ошибка выделения памяти в стеке JVM приводит `StackOverflowError`.
Если же реализация JVM допускает динамическое расширение размера стека JVM, но во время расширения возникает ошибка памяти, JVM выдаст `OutOfMemoryError`.

##### Фрейм (Stack Frame)
Каждый фрейм хранит массив локальных переменных, стек операндов и ссылку на пул констант времени выполнения метода.

Фреймы обычно размещаются в стеке JVM, но спецификация допускает их размещение в куче.

В стеке хранятся примитивные типы данных и сами ссылки на объекты.

### Native Method Stacks
Native метод - это метод, написанный на другом языке программирования, отличном от Java. Такие методы не компилируются в байт-код, поэтому требуют другую область памяти.

Стек native методов очень похож на стек JVM, но предназначен только для собственных методов. Он должен отслеживать выполнение native метода.

Реализация JVM может самостоятельно определять размер стека native методов и то, как он обрабатывает блоки памяти.

Ошибка выделения памяти в стеке native методов вызывает `StackOverflowError`. Но неудачная попытка увеличить размер стека native методов приводит к `OutOfMemoryError`.

**Замечание**: Конкретная реализация JVM может не поддерживать вызовы native методов, а значит ей не нужно реализовывать стек native методов.
