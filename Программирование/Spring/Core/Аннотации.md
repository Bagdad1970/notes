## @Configuration
Аннотация уровня класса.
Указывает, что объект является источником определений бинов. Классы `@Configuration` объявляют бины с помощью аннотации `@Bean`.
```java
@Configuration
public class AppConfig {

	@Bean
	public BeanOne beanOne() {
		return new BeanOne(beanTwo());
	}
	
	@Bean
	public BeanTwo beanTwo() {
		return new BeanTwo();
	}
}
```


## @Bean
Аннотация уровня методы.
Регистрирует объект, возвращаемый методом, как бин. Spring вызывает этот метод, если требуется создать экземпляр возвращаемого типа.
```java
@Configuration  
public class AppConfig {  
  
    @Bean  
    public MyBeanClass myBeanOne() {  
        return new MyBeanClass();  
    }  
}
```

## @Component
Аннотация уровня класса.
Указывает, что класс управляется IoC контейнером Spring.

## @Service
Аналогичен @Component, но помечает классы сервисного слоя. 

## @Repository
Аналогичен @Component, но помечает классы слоя хранения данных. Также он  перехватывает исключения слоя хранения данных, зависящие от платформы, и ==повторно генерировать их как одно из унифицированных непроверенных исключений Spring==

## @Controller
Аналогичен @Component, но помечает классы слоя ==контроллеров==. Диспетчер  

## @Primary
Указывается, если необходимо дать одному из нескольких ==одинаковых== бинов, большее предпочтение

**Замечание**: что значит одинаковые бины

Пример:
```java
@Configuration
public class Config {
    @Bean
    @Primary  // (1)
    public Employee JohnEmployee() {
        return new Employee("John");
    }

    @Bean
    public Employee TonyEmployee() {
        return new Employee("Tony");
    }
}

...

AnnotationConfigApplicationContext context = new AnnotationConfigApplicationContext(Config.class);  
  
Employee employee = context.getBean(Employee.class);  // здесь возникнет исключение
```
(1) - Если не указать @Primary, то при попытке получить bean, возникнет исключение `NoUniqueBeanDefinitionException`.

https://www.baeldung.com/spring-primary


## @Qualifier
Используется для устранения неоднозначности, когда для внедрения зависимостей доступно несколько бинов одного типа. Она позволяет указать, какой именно бин нужно внедрить в класс.

Пример:
```java
public interface Formatter { String format(); }

@Component("formatter1")  // (1)
public class FooFormatter implements Formatter {  
    @Override  
    public String format() { return "foo"; }
}

@Component("formatter2")
public class BarFormatter implements Formatter {  
    @Override  
    public String format() { return "bar"; }  
}

@Component  
public class ServiceImpl {  
    private final Formatter formatter;  
  
    @Autowired  
    public ServiceImpl(@Qualifier("formatter1") Formatter formatter) {  // (2)
        this.formatter = formatter;  
    }  
    
    public String format() {  
        return formatter.format();  
    }  
}
```
(1) - Можно не указывать отдельно название компоненты и указать в @Qualifier fooFormatter.
(2) - Указываем какую компоненту использовать в конструкторе

https://www.geeksforgeeks.org/springboot/spring-qualifier-annotation-with-example/
https://www.baeldung.com/spring-qualifier-annotation


## @Autowired
Позволяет Spring разрешать и внедрять зависимости во время инициализации бина.
Может применяться на полях ([не надо](https://habr.com/ru/articles/983344/)), сеттерах и конструкторах.

Пример для конструктора:
```java
@Component  
public class FooService {  
    ... 
}

@Component  
public class BarService {  
    ...
}

@RestController  
@RequestMapping("/api/tests")  
public class FooController {  
    private final FooService fooService;  
    private final BarService barService;  
  
    @Autowired  // (1)
    public FooController(FooService fooService) {  
        this.fooService = fooService;  
        this.barService = null;  
    }  
      
    public FooController(FooService fooService, BarService barService) {  
        this.fooService = fooService;  
        this.barService = barService;  
    }
    
	...
	
}
```
(1) - Помечает тот конструктор, который должен использоваться для создания бина.

**Замечание**: Начиная с Spring Framework 4.3 можно не указывать @Autowired для конструктора, если он один в бине.
