




### SecurityContextHolder 
Хранит информацию о текущем контексте безопасности приложения, который включает в себя подробную информацию о текущем пользователе.

### SecurityContext
Хранит экземпляр `Authentication`.
Обычно хранится в Thread-local переменной, чтобы информация о безопасности относилась только к текущему потоку.

### Authentication
Служит двум  целям:
1. Для ввода в `AuthenticationManager` учетных данных, которые пользователь предоставил для аутентификации. В этом случае isAuthenticated() возвращает false.
2. Хранит пользователя, прошедшего проверку подлинности в данный момент.

`Authentication` содержит:
1. `principal`: Идентифицирует пользователя. При аутентификации с использованием имени пользователя/пароля это часто является экземпляром `UserDetails`.
2. `credentials`: Зачастую это пароль. Во многих случаях этот параметр снимается после аутентификации пользователя, чтобы предотвратить утечку данных.
3. `authorities`: Экземпляр `GrantedAuthority` - это разрешения высокого уровня, которые предоставляются пользователю. Двумя примерами являются роли и области действия.

### AuthenticationManager
```java
@FunctionInterface
interface AuthenticationManager {
	Authentication authenticate(Authentication authentication)
}
```
Метод `authenticate()` пытается выполнить аутентификацию для переданного объекта `Authentication`. В случае успеха возвращает заполненный объект аутентификации (включая предоставленные полномочия).

Реализация определяет, как фильтры выполняют аутентификацию. Возвращаемый `Authentication` затем используется в `SecurityContextHolder` контроллером, который вызвал `AuthenticationManager`. Если фильтры не используются, то можно напрямую установить `SecurityContextHolder` и не использовать `AuthenticationManager`.

Наиболее распространенной реализацией `AuthenticationManager` является `ProviderManager`.

### ProviderManager
`ProviderManager` предоставляет доступ к списку экземпляров `AuthenticationProvider`. Каждый `AuthenticationProvider` имеет возможность указать, что аутентификация должна быть успешной, завершиться неудачей или указать, что он не может принять решение, и предоставить право принятия решения нижестоящему `AuthenticationProvider`. Если ни один из настроенных экземпляров `AuthenticationProvider` не может успешно выполнить проверку ==подлинности==, то генерируется исключение `ProviderNotFoundException`. `ProviderNotFoundException` является специальным исключением `AuthenticationException`, указывающим на то, что `ProviderManager` не был настроен для поддержки переданного в него типа аутентификации.
![[Pasted image 20260403185740.png|561]]


На практике каждый `AuthenticationProvider` знает, как выполнить определенный тип аутентификации. Например, один `AuthenticationProvider` используется для аутентификации с именем пользователя и паролем, а другой для аутентификации через SAML. Это позволяет каждому `AuthenticationProvider` выполнять специфический тип аутентификации, поддерживая при этом несколько типов аутентификации и предоставляя доступ только к одному бину `AuthenticationManager`.

### UserDetails
Предоставляет основную информацию о пользователях, которая используется для создания объектов Authentication из DAO объектов приложения или других источников данных системы безопасности. Позволяет хранить информацию о пользователях, не связанную с безопасностью (например, адреса электронной почты, номера телефонов и т.д.).

### UserDetailsService
```java
@FunctionalInterface
interface UserDetailsService {
	UserDetails loadUserByUsername(String username);
}
```
Метод `loadUserByUsername()` находит пользователя по имени пользователя. В реальной реализации поиск может быть чувствительным к регистру или без учета регистра в зависимости от того, как настроен экземпляр реализации. В этом случае возвращаемый объект UserDetails может содержать имя пользователя, которое отличается от того, которое было запрошено на самом деле.
