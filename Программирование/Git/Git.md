Git — система управления версиями с распределенной архитектурой. Вместо сохранения изменений кода в Git используются снимки (snapshots).

Концептуально, большинство других систем хранят информацию в виде списка изменений в файлах. Вместо этого Git к хранит данные как набор снимков миниатюрной файловой системы. 

![[Pasted image 20260525191755.png|697]]


Git snapshot - это полное представление кодовой базы в определенный момент. Каждый снимок фиксирует все файлы и папки и уникально идентифицируется с помощью хэша SHA-1, который отражает содержимое снимка. Причем если файлы не были изменены, Git лишь создаёт ссылку на предыдущую версию уже сохраненного файла. В дальнейшем обращение к сохранённым объектам происходит по этому хэшу. Этот хэш гарантирует, что даже малейшее изменение в коде приведет к появлению совершенно другого идентификатора, сохраняя целостность вашей истории версий.

Git хранит эти снимки в KV-базе данных в каталоге `.git`.



## Структура каталога `.git`

Примерная структура директории `.git` имеет следующий вид:
```
.git  
├── COMMIT_EDITMSG  # сообщение последнего коммита
├── config  # конфигурация репозитория
├── description  # описание (используется GitWeb)
├── HEAD  # указатель на текущую ветку или коммит
├── hooks/  # скрипты-хуки
├── index  # staging area (индекс)
├── logs/  # логирует все перемещения указателя HEAD и изменения веток
│   ├── HEAD  
│   └── refs/  
│       └── heads  
│           └── master  
├── objects/  # все объекты Git
│   ├── 03/  
│   │   └── c3e0b6342eb7d22cf964797a3877cd03054a62  # объект с хешем 03c3e0...
│   ├── info/  
│   └── pack/  # упакованные объекты
└── refs/  # указатели на конкретные коммиты.
   ├── heads/  
   │   └── master  # файл с хешем коммита ветки master
   ├── remotes/  # Ветки в удаленных репозиториях.
   └── tags/  # теги

```


Каждый объект представляется в памяти в виде заголовка и содержимого, сжатого алгоритмом zlib. Заголовок состоит из типа объекта, размера содержимого в байтах и нулевого байта, который отделяет заголовок.
Объекты можно разделить на несколько типов:
1. Commit
2. Blob
3. Tree
4. Tag

### Commit
Представляет определенный момент в истории проекта. Каждый коммит содержит важную информацию, в том числе:
	- Объект дерева: ссылка на моментальный снимок файловой структуры проекта.
	- Родительский объект фиксации: ссылки на предыдущую фиксацию, позволяющие создавать хронологическую цепочку.
	- Автор: Пользователь, который внес изменения.
	- Отправитель: Пользователь, который применил изменения.
	- Сообщение о фиксации: Краткое описание внесенных изменений.


### Blob
Хранит фактическое содержимое файлов в двоичном виде. При изменении файла, blob-объект сохраняет данные этого файла, инкапсулируя само содержимое без каких-либо дополнительных метаданных.


### Tree
Действует как контейнер для всех файлов и папок в определенном состоянии проекта.
Объекты tree будут вершинами дерева, отвечающими за папки. Корневую вершину тоже можно считать папкой. В качестве содержимого будут храниться ребра, которые представляют указатели на следующие вершины дерева.
Содержит:
	- **Файловый режим** - права доступа, связанные с каждым файлом;
	- **Название файла**;
	- **Хэш файла**;
	- **Объект родительского дерева** - ссылка на предыдущее состояние дерева, поддерживающее родословную.

Объект tree организует структуру проекта в виде иерархии файлов и каталогов, сохраняя их в виде пар ключ-значение, где ключом является имя файла, а значением - хэш файла.




Файл в Git может находиться в следующих состояниях:
- **Изменен (modified)**. Файлы изменился, но изменения еще не были зафиксированы;
- **Индексирован (staged)**. Изменённый файл в его текущей версии, отмеченный для включения в следующий коммит.
- **Зафиксирован (commited)**. Файл уже сохранён в локальной базе.
