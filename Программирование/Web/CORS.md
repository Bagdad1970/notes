**Источник** веб-содержимого определяется частями URL, который был использован для доступа к ресурсу: _схема_ (протокол), _имя хоста_ (домен), и _порт_.
Два документа имеют одинаковый источник только когда схема, имя хоста и порт совпадают.
Пример: `http://example.com` и `https://example.com` отличаются следующими элементами: протоколом, портами (http - 80, https - 443). Следовательно, в данном примере источники различны.

Пример cross-origin запроса:
**Субресурс**  — это HTML элемент, который требуется вставить в документ или выполнить  в контексте этого документа. Если браузер отображает страницу с `<img>`, он должен запросить этот тег из источника. Если браузер запрашивает тег из другого источника, то это и есть запрос между различными источниками (cross-origin request).

**SOP** (Same-Origin Policy, Принцип Одинакового Источника) - механизм, позволяющий скриптам, находящимся на одной веб-странице получить данные на второй веб-странице, но только если обе веб-страницы имеют одинаковый источник. Политика ограничивает вредоносным скриптам с одной страницы получение доступа к чувствительной информации на другой странице через DOM-дерево данной страницы. Такие ресурсы, как изображения, CSS и динамически-загружаемые скрипты могут быть доступны из любого источника через соответствующие HTML-теги (за исключением шрифтов).

**CORS** (Cross-Origin Resource Sharing, Совместное Использование Ресурсов Между Разными Источниками) - механизм, использующий дополнительные HTTP заголовки, чтобы дать возможность агенту пользователя получать разрешения на доступ к выбранным ресурсам с сервера на источнике, отличном от текущего.

**Предварительный (preflight) запрос** - [[HTTP#OPTIONS|OPTIONS]] запрос, отправляемый браузером к ресурсу на другом домене, чтобы определить, является ли фактический запрос безопасным для отправки. Ответ на этот запрос будет содержать заголовки `Access-Control-*`. Такой запрос к другому источнику проходит предварительную проверку, поскольку он может влиять на пользовательские данные.

Запрос считается небезопасным, если:
- Запрос использует методы отличные от GET, POST, или HEAD
- Имеются заголовки отличные от Accept, Accept-Language, Content-Type или Content-Language
- Значение заголовка Content-Type отличное от application/x-www-form-urlencoded, multipart/form-data, или text/plain.

### Заголовки CORS
Заголовки запросов:
1. `Origin` - представляет источник
2. `Access-Control-Request-Method` - используется для предварительных запросов и указывает фактический метод запроса.
3. `Access-Control-Request-Headers` - используется для предварительных запросов и содержит пользовательские заголовки фактического запроса.
   Пример: `Authorization, X-PING`

Заголовки ответов:
1. `Access-Control-Allow-Origin` – указывает каким источникам (`Origin`), доступны запросы к сайту. Может быть `*`, тогда любому источнику доступны запросы к сайту. Браузер сравнивает источник разрешения доступа с источником запрашивающего сайта (`Origin`) и разрешает доступ к ответу, если они совпадают.
   `https://www.google.com/`
2. `Access-Control-Allow-Methods` – указывает, какие HTTP-методы разрешены для запросов к источнику.
3. `Access-Control-Allow-Headers` используется в ответ на preflight request, чтобы указать, какие заголовки HTTP могут использоваться фактическим запросом.
4. `Access-Control-Max-Age` указывает на сколько секунд кэшируются результаты preflight запросов (т.е. заголовков `Access-Control-Allow-Headers` и `Access-Control-Allow-Methods`)
5. `Access-Control-Expose-Headers` указывает какие заголовки ответов доступны при запросах из разных источников. По умолчанию доступны только заголовки ответов, внесенные в список защищенных в CORS.
6. `Access-Control-Allow-Credentials` сообщает браузерам, разрешает ли сервер включать учетные данные в HTTP-запросы разных источников. Учетные данные включают файлы cookie, клиентские сертификаты транспортного уровня (TLS) или заголовки проверки подлинности, содержащие имя пользователя и пароль. По умолчанию эти учетные данные не отправляются в запросах от разных источников, и это может сделать сайт уязвимым для атак на подделку межсайтовых запросов ([[CSRF]]).
   Если учетные данные включены:
   - Preflight запрос: предполетный запрос не содержит учетных данных. Если в ответе сервера на preflight запрос `Access-Control-Allow-Credentials = true`, то фактический запрос будет содержать учетные данные; в противном случае браузер сообщит о сетевой ошибке.
   - Для запросов без предварительной настройки: Запрос будет содержать учетные данные, и если в ответе сервера для заголовка `Access-Control-Allow-Credentials = false`, браузер сообщит о сетевой ошибке.

### Практика
```crystal
require "kemal"

port = ENV["PORT"].to_i || 4000

get "/" do
  "Hello world!"
end

get "/greet" do |env|
  env.response.headers["Access-Control-Allow-Origin"] = "https://www.google.com" (1)
  "Hey!"
end

options "/greet" do |env| (2)
  env.response.headers["Access-Control-Allow-Methods"] = "POST"
  env.response.headers["Access-Control-Allow-Headers"] = "Content-type"
  env.response.headers["Access-Control-Allow-Origin"] = "https://www.google.com"
end

post "/greet" do |env|
  name = env.params.json["name"].as(String)

  env.response.headers["Access-Control-Allow-Origin"] = "https://www.google.com" (3)

  "Hello, #{name}!"
end


Kemal.config.port = 4000
Kemal.run
```
(1), (3) - указываем `Access-Control-Allow-Origin`, чтобы браузер отобразил ответ сервера
(2) - модифицируем OPTION запрос
