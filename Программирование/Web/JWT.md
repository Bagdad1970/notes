JSON Web Token (JWT) - это стандарт, который определяет компактный и автономный способ безопасной передачи информации между сторонами в виде объекта JSON. Эта информация имеет цифровую подпись.
JWT могут быть подписаны с использованием секретного ключа (с помощью алгоритма HMAC) или пары открытого/закрытого ключей с использованием RSA или ECDSA.

## Структура JWT

### Header
Состоит обычно из двух частей: типа токена, которым является JWT, и используемого алгоритма подписи.
Пример:
```json
{
  "alg": "HS256",
  "typ": "JWT"
}
```

### Payload
Содержит утверждения (claims). Claims содержат утверждения о сущности (например, пользователе) и доп. информацию.
Виды claims:
1. Зарегистрированные. Представляют собой предопределенные стандартом утверждения, которые рекомендованы к использованию
2. Публичные - имена утверждений в масштабе системы. Во избежание коллизий, утверждения следует регистрировать в IANA Json Web Token Registry или использовать в качестве префикса доменное имя, устойчивое к коллизиям.
3. Приватные - пользовательские утверждения, созданные для обмена информацией между сторонами, которые договорились об их использовании, причем утвреждения не являются зарегистрированными или публичными.

Зарегистрированные claims:
- `iss` — (issuer) издатель токена;
- `sub` — (subject) назначение токена;
- `aud` — (audience) аудитория, для которой предназначен токен;
- `exp` — (expire time) срок действия токена;
- `nbf` — (not before) время, до которого токен недействителен;
- `iat` — (issued at) время создания токена;
- `jti` — (JWT id) уникальный идентификатор токена.

Пример:
```json
{
  "sub": "1234567890",
  "name": "John Doe",
  "admin": true
}
```

### Signature
Используется для подтверждения неизменности сообщения в ходе передачи и, если токен был подписан секретным ключом, сигнатура может подтвердить личность отправителя.

Вычисление сигнатуры выглядит следующим образом: 
```
Метод_Хэширования(
  base64UrlEncode(header) + "." +
  base64UrlEncode(payload),
  secret)
```


Для генерации JWT каждая часть токена кодируется как Base64-URL.

На выходе получается строка вида:
`base64(header).base64(payload).base64(signature)`
