


Процесс обработки запроса Django:
1. Определяется корневой модуль URLconf (URL configuration), который будет использован для сопоставления URL  использовать. Обычно URLconf указывается в переменной окружения `ROOT_URLCONF`. Однако входящий объект HttpRequest может иметь атрибут `urlconf` , установленный middleware. Тогда его значение будет использоваться в качестве `ROOT_URLCONF`. 
2. Загружает модуль Python
3. Ищется первый шаблон в `urlpatterns`, который соответствует запрошенному URL, сопоставляя его с ~={red}path_info=~.
4. При совпадении одного из шаблонов URL импортирует и вызывает указанное представление, которое представляет собой функцию Python или представление на основе классов.
   Представлению передаются следующие аргументы:
	- Объект HttpRequest;
    - Если в совпадающем шаблоне URL не было именованных групп, то совпадения из регулярного выражения передаются в качестве позиционных аргументов.
    - Аргументы ключевого слова состоят из всех именованных частей, соответствующих выражению пути, которые переопределяются любыми аргументами, указанными в необязательном аргументе kwargs для django.urls.path() или django.urls.re_path().
5. Если ни один шаблон URL не подходит или на каком-либо этапе возникает исключение, Django вызывает соответствующее представление для обработки ошибок.

Пример URLconf:
```python
from django.urls import path
from . import views

urlpatterns = [
    path("articles/2003/", views.special_case_2003),
    path("articles/<int:year>/", views.year_archive),
    path("articles/<int:year>/<int:month>/", views.month_archive),
    path("articles/<int:year>/<int:month>/<slug:slug>/", views.article_detail),
]
```

### Функции

`path(route, view, kwargs=None, name=None)` - сопоставляет путь URL с представлением (функцией или классом представления).
Параметры:
- `route` - представляет шаблон адреса URL, которому должен соответствовать запрос;
- `view` - представление, которое обрабатывает запрос. Когда Django находит подходящий шаблон, он вызывает указанную функцию представления с объектом HttpRequest в качестве первого аргумента и всеми «захваченными» значениями из маршрута в качестве аргументов-ключевых слов.;
- `kwargs` - дополнительные аргументы, которые передаются в представление;
- `name` - ==название маршрута==.

`re_path(route, view, kwargs=None, name=None)` - модификация `path`, которая позволяет задавать пути регулярными выражениями.
Параметры аналогичны параметрам `path`.



include()

- **`urlpatterns`**: Список, содержащий функции `path()` или `re_path()`, которые сопоставляют URL с логикой.
- **`include()`**: Функция, позволяющая подключать файлы маршрутизации из отдельных приложений (модульность).
