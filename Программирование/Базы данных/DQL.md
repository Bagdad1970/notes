DQL - подмножество языка SQL, предназначенное для выполнения запросов к БД с целью извлечения данных.

## Порядок описания запроса
Структура запроса имеет следующий порядок команд:
1. `SELECT`
2. `DISTINCT`
3. `FROM`
4. `JOIN`
5. `WHERE`
6. `GROUP BY`
7. `HAVING`
8. `ORDER BY`
9. `LIMIT / OFFSET`

## Порядок выполнения запроса
Порядок выполнения запроса отличается от порядка описания:
1. **FROM & JOIN** - формирование набора данных для обработки
2. **WHERE** - отбираются записи в соответствии с условием
3. **GROUP BY** - выбранные записи агрегируются
4. **HAVING** - отбираются агрегированные записи
5. **SELECT** - формируются данные результирующей выборки (вычисляются выражения, присваиваются имена столбцам)
6. **DISTINCT** - удаляются дубликаты строк
7. **ORDER BY** - результирующая выборка сортируется
8. **LIMIT & OFFSET** - выбирается страница результата

## Оператор JOIN
**JOIN** - семейство команд, которые соединяют данные из разных таблиц в одну выборку. По умолчанию используется INNER JOIN.

Виды JOIN:
1. **INNER JOIN** - выбираются только строки, у которых есть совпадение по заданному условию.
2. **LEFT JOIN (LEFT OUTER JOIN)** - возвращает все строки из левой таблицы и только совпадающие строки из правой. Если совпадения нет, поля правой таблицы содержат `NULL`.
3. **RIGHT JOIN (RIGHT OUTER JOIN)** - возвращает все строки из правой таблицы и только совпадающие строки из левой. Если совпадения нет, поля левой таблицы содержат `NULL`.
4. **FULL JOIN (FULL OUTER JOIN)** - выбираются строки из обеих таблиц. Если есть совпадения, данные объединяются, а где связи нет — незаполненные поля заменяются NULL.
5. **CROSS JOIN** - декартово произведение таблиц.
6. **SELF JOIN** - таблица, соединяется сама с собой. Например, в таблице сотрудников у каждого может быть поле manager_id. Соединив таблицу с самой собой по этому полю, можно понять, кто является начальником конкретного сотрудника.

Структура запроса:
```sql
SELECT ...
FROM table1 [тип_соединения] JOIN table2 ON table1.table2_id = table2.table1_id;
```

## Оператор WHERE
**WHERE** описывает условия, которым должна удовлетворять строка. Если запись удовлетворяет этому условию, то попадает в результат, иначе отбрасывается.

## Оператор GROUP BY
GROUP BY группирует по столбцам записи, имеющие одинаковые значения в указанных столбцах.
```sql
GROUP BY column_1, ..., column_n;
```

При использовании GROUP BY можно выводить только:
- литералы (фиксированные значения).
- результаты агрегатных функций
- поля группировки. Мы можем их выводить, так как в рамках одной группы поля, по которым осуществлялась группировка, одинаковые
- поля, функционально зависящие от полей группировки (например, если группировка идёт по первичному ключу `id`, то можно вывести `name`, потому что он однозначно определяется этим `id`). Однако такая возможность зависит от СУБД и её настроек, поэтому для переносимости запроса лучше явно добавлять такие поля в `GROUP BY`.

## Оператор HAVING
**HAVING** фильтрует ==сгруппированные== данные и используется для работы с агрегатными функциями.

**Замечание**: `HAVING` может использоваться без `GROUP BY`, тогда вся таблица считается одной группой.

## Оператор ORDER BY
**ORDER BY** используется для упорядочивания записей.
При выполнении SELECT запроса, строки по умолчанию возвращаются в неопределённом порядке. Фактический порядок строк в этом случае зависит от плана соединения и сканирования, а также от порядка расположения данных на диске.
```sql
SELECT column_1, ..., column_n FROM table
ORDER BY column1 [ASC | DESC][, .., column_n [ASC | DESC]]
```
`ASC` - сортировка по возрастанию (по умолчанию)
`DESC` - сортировка по убыванию

#### Сортировка для основных типов данных

| Тип данных    | ASC                                                                                                                                                | DESC                                                                                                                         |
| :------------ | :------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| Строковый тип | Лексикографический (алфавитный) порядок от «A» до «Z» (или от «А» до «Я»)  <br>  <br>Сначала идут записи, начинающиеся на «a», затем на «b» и т.д. | Лексикографический порядок от «Z» до «A» (или от «Я» до «А»)  <br>  <br>Сначала идут записи, начинающиеся на «z», «y» и т.д. |
| Числовой тип  | От меньшего к большему                                                                                                                             | От большего к меньшему                                                                                                       |
| Дата и время  | От более ранней даты/времени к более поздней                                                                                                       | От более поздней даты/времени к более ранней                                                                                 |
| Булевый тип   | false, true                                                                                                                                        | true, false                                                                                                                  |
| NULL значения | NULL значения идут последними*                                                                                                                     | NULL значения идут первыми*                                                                                                  |
\* - зависит от СУБД. NULL значения могут считаться максимально возможным.

#### Сортировка по нескольким столбцам
Данные будут сортироваться по первому столбцу, но в случае если попадаются несколько записей с совпадающими значениями в первом столбце, то они сортируются по второму столбцу. Количество столбцов, по которым можно отсортировать, не ограничено.
```sql
...ORDER BY column_1 [ASC | DESC], column_2 [ASC | DESC];
```

### Оператор DISTINCT
**DISTINCT** убирает дубликаты строк из выборки.
Для двух и более столбцов будут удаляться записи, которые имеют одинаковые значения по всем полям.
```sql
SELECT DISTINCT column_1, ..., column_n FROM table;
```

DISTINCT может быть реализован через сортировку или хэширование:
1. **Сортировка**. Данные сортируются по всем столбцам выборки, затем удаляются все идущие подряд одинаковые строки.
2. **Хэширование**. Для каждой строки вычисляется хэш-значение на основе уникальных столбцов. Если хэш-значение уже есть в хэш-таблице, строка отбрасывается как дубликат, иначе - добавляется.

**Замечание**: `DISTINCT` считает все `NULL` значения одинаковыми, поэтому возвращает только одно значение `NULL`, если оно встречается в столбце.
